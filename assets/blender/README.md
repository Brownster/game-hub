# Blender asset pipeline

Game art that can be rebuilt from source. Every asset here is generated by a
script and rendered headlessly, so re-rendering at a new resolution, adjusting a
colour, or reproducing a sprite in a year's time is a command rather than an
archaeology exercise.

Nothing in this directory is required to run GameHub. The rendered PNGs are
committed under `services/web/public/`; this is how they were made.

## Requirements

Blender 5.1 or newer, on PATH:

```bash
blender --version
```

Installed here at `~/.local/opt/blender-5.2.2-linux-x64`, symlinked into
`~/.local/bin`. Nothing else is needed: no add-ons, no `.blend` files, no MCP
server. The scripts build their geometry, materials, lighting and camera from
scratch on every run.

## Rendering the chess set

```bash
npm run --prefix services/web assets:chess
```

That runs two stages: Blender renders into `services/web/.render-cache/chess`
(gitignored), then `trim_sprites.py` crops each sprite to its alpha bounding box
on the way into `services/web/public/chess/pieces/wood`. To run just the render:

```bash
blender --background --python assets/blender/render_chess.py -- \
  --out /tmp/chess --resolution 512 --samples 96
```

Options:

| Flag | Default | Notes |
|---|---|---|
| `--out` | required | Output directory; written as `w_pawn.png`, `b_king.png`, … |
| `--resolution` | 512 | Square canvas, transparent background |
| `--samples` | 128 | Cycles samples. 32 is fine for checking shape |
| `--only` | all | Render one piece, e.g. `--only knight` |

A full set at 512px takes a few minutes on 8 CPU cores. Use
`--resolution 256 --samples 32` while iterating on geometry; it is roughly
sixteen times faster and shape problems show up just as clearly.

## How the chess pieces are built

`chesslib.py` holds the geometry primitives, `render_chess.py` the scene.

Every piece except the knight is a **lathed profile** — a list of
`(radius, height)` points spun around Z, which is how chess pieces are actually
turned. Changing a piece means editing numbers in a profile function, not
pushing vertices in a GUI.

- **Pawn, bishop, queen, king** — lathe, plus booleans for the queen's coronet
  and geometry for the king's cross.
- **Rook** — lathe, with four cubes cut through the battlement rim.
- **Knight** — cannot be lathed. A filled 2D curve with extrude and bevel
  (`KNIGHT_SILHOUETTE`), joined to a turned pedestal.

Heights live in `chesslib.PIECE_HEIGHTS` in "pawn units", so the set stays in
proportion. One orthographic camera frames the tallest piece and renders every
piece through it, so a pawn is genuinely shorter than a king in the raw render.

That honest proportion does not survive contact with a chessboard: on squares of
equal size the pawns floated with dead space around them and looked undersized.
So `trim_sprites.py` crops each sprite to its own content as a second stage, and
the board CSS sizes each piece to fill its square — which is what the original
flat art did. The render keeps the true proportions; trimming is a presentation
choice applied on the way out, and dropping it is a one-line change.

Piece colours are **boxwood** (`#f0e2c8`) and **ebony** (`#3b2415`), converted
sRGB → linear on the way in. They deliberately do *not* use `--wood-light` and
`--wood-dark`: those are the board square colours, and the first render in those
tones left the light pieces almost invisible on light squares. Real sets use
boxwood and ebony for the same reason — pieces have to bracket the board's tonal
range from outside it.

## Gotchas worth keeping

These each cost a render cycle to find:

- **Colour sockets are linear, CSS hex is sRGB.** Feeding hex values straight
  into Blender gives washed-out, desaturated material. Use `hex_to_linear()`.
- **View transform must be `Standard`.** AgX and Filmic apply a film curve that
  shifts the result away from the chosen colours.
- **A boolean leaves an empty material slot behind**, inherited from the cutter.
  Appending a material after a boolean puts it at index 1 while every polygon
  still points at slot 0, and the piece renders Cycles default grey. Always
  `materials.clear()` first.
- **Exposure is easier to measure than to eyeball.** Compare the 95th-percentile
  luminance of the non-transparent pixels against the target colour's luminance.
- **Pieces must contrast with the board, not match it.** Check a render
  composited on both square colours before calling a palette done.
- **Curve-derived meshes are not clean enough for exact-solver booleans.** The
  knight's head is joined to its pedestal, not unioned.

## Adding another asset script

Follow the same shape: build geometry from code, choose colours by value
against whatever they will sit on, render through one camera with
`film_transparent`, take `--out` and
`--resolution` on the command line, and keep a fixed `cycles.seed` so repeat
runs are byte-comparable. Candidates worth doing next are Catan hex tiles with
real bevel and depth, dice, and card backs — the Catan icons should stay SVG.
